# iOS 原生工程与数据规范

## 内容

`prepare-data.mjs` 调用现有历史内容编译器。仓库中已有书卷、专题、场景、疆域和史事数据保持编辑权威。App 不引入独立编辑数据库。身份稳定性、审校范围、路线准确度和来源协议沿用现有历史规范。

运行包以 `OfflineData/Manifest.json` 标识数据结构版本和资源摘要。内容版本由规范化资源字节确定。App 版本与构建号由工程配置决定。两者按各自变化更新。

`Library.json` 包含书目、章节索引、规范史事和去重成员。章正文与注释按稳定身份生成资源文件，由 `ChapterStore` 按需读取并限制缓存。地图索引分开保存主体、书卷关联、底图覆盖与参考边界。场景阶段保留有效地点、路线、重点政权、证据和精度。原始身份记录、地图绑定审校及暂停场景在 `Editorial.json` 留存。检索使用已有标题、译名和别名。没有证据支持的地区分类留为未标注。

## 职责与生命周期

- `HistoryData`、`Search` 保存不可变内容及检索索引。应用初始化发现资源失败时允许重试。
- `SessionStore` 持有探索、阅读栈、临时面板和观察来源。目标年份、已应用底图和观察年份独立。会话、偏好和逐卷进度用单一可版本化存储记录。0.1.1 旧键保留，首次读取后按新格式写入。
- `GlobeSurface` 在 UIKit 层用按需 `CADisplayLink` 管理触点、镜头、惯性与动画。一帧只交付一个镜头快照。Metal、标注、场景路线与热点拾取共享此投影。SwiftUI 接收应用底图、选择和镜头停稳事件。
- `Atlas` 将原始多边形派生成覆盖纹理、球面线段及拾取路径。CPU 和 GPU 分别缓存，切年可取消过期请求。缩放复用同一份矢量边界，快速切年时只允许拾取已完成的新底图。
- 地表在线性色域计算光照，颜色纹理采用 sRGB 解码，地形法线、云和疆域遮罩保留线性采样。纹理使用 mipmaps，疆界通过屏幕空间抗锯齿矢量绘制。标签由 `GlobeAnnotations` 根据投影面积、可视区域、碰撞预算和优先级布局。
- `MapPanel` 提供两档停靠，原生滚动在回到顶部后可把同一次下拉交给抽屉。容器统一计算纸面背景、安全区、裁剪和真实地图遮挡。地图避让基于头尾控件和实时抽屉高度。旧会话的 0/1 迁移到小屏，2 保留为全屏。
- `ExplorerView`、`ReadingViews`、`ChapterPage`、`ObservationView`、`CompanionView` 读取统一会话及内容。阅读通过块 ID 和按比例记录的段内位置恢复。观察期间保留来源正文。当场景数据不足时显示自然地形、位置限制或可重试状态。
- `DesignSystem`、`TimelineView`、`Haptics` 定义两类界面颜色、排版、辅助纸面、原生滚动和反馈规则。

## 发布

`codex/ios-native` 从当前分支推送构建。保留 Bundle ID `io.github.lllliam.spacetimeglobe.native` 与 iOS 16 目标。工程生成、数据校验、原生编译和 IPA 签名结构检查通过后才打包，模拟器检查关键流程。涉及历史资料的更改应走原有内容校验。测试记录要区分模拟器、真机及实际侧载签名。设备实际刷新率和性能允许时请求 60 Hz 以上刷新，帧率以真机测量为准。
