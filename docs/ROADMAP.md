# Spacetime Globe 1.0 开发路线

阶段顺序已冻结。产品决策见 [产品规范](PRODUCT-SPEC.md)，最终发布门槛见 [验收标准](ACCEPTANCE.md)。以下工作范围和交付是阶段边界，具体实现等待产品负责人逐轮下达完整指令。

| --- | --- | --- | --- | --- | --- |
| 1.0 · Phase 01 | 完成 | 版本体系、工程审查、历史归档、产品规范和固定路线 | v14.2.1 原型与本轮指令 | 修改运行时、内容、部署或发布 1.0 | 五份核心文档、README、维护约定和原型档案齐备。检查链接、历史、工作区范围并记录真实验证结果 |
| 1.0 · Phase 02 | 完成 | 统一 Explore、Read、Observe 的状态、导航、上下文恢复和持久化底层 | Phase 01 完成及本轮指令 | 提前改造首页、重写内容或改正式版本号 | 已验证核心导航、刷新和浏览器重启恢复，现有入口与在线、离线数据保持兼容。见 [状态模型](STATE-MODEL.md) |
| 1.0 · Phase 03 | 完成 | 地球首页、首次启动、时间交互、主体选取、摘要及控件体系 | Phase 02 的状态和恢复机制及本轮指令 | 提前重做书卷正文或迁移历史模型 | 1500 年历史疆域首启，统一选年、显式史事和阅读入口、会话恢复与六种视口通过。见 [阶段报告](progress/PHASE-03.md) |
| 1.0 · Phase 04 | 完成 | 全屏阅读、目录章节导航、正文排版、进度、来源与无障碍 | 已有状态接口与探索入口及本轮指令 | 提前治理全库正文或建设新地图场景 | 手机与桌面仅用全屏书卷，目录、引用、键盘、旧半屏会话、字号重排和独立观察往返均通过验证。[阶段报告](progress/PHASE-04.md) |
| 1.0 · Phase 05 | 完成 | 区分地理、政权、文明与历史叙事，解除固定内容模板并兼容迁移 | 已明确的探索、阅读入口及本轮指令 | 删除存量内容、任意重置稳定 ID 或提前改写史实 | 存量关系与正文快照一致，地图入口区分主叙事与相关历史，稳定引用及旧会话迁移通过验证。[阶段报告](progress/PHASE-05.md) |
| 1.0 · Phase 06 | 完成 | 独立地图观察、书球往返、多阶段场景及全球关联 | Phase 05 数据边界、Phase 02/04 状态与阅读接口及本轮指令 | 自动打开正文场景、绘制超出证据精度的路线或把共时当联系 | 48 个场景有逐项处置，独立阶段和来源返回通过验证，关联按共时、比较与实际联系呈现。[阶段报告](progress/PHASE-06.md) |

| 1.0 · Phase 08 | 待指令 | 完成《明朝》标杆书卷的叙事、空间解释和可信史料体系 | Phase 07 的治理流程与前序阅读、场景能力及本轮指令 | 把原型《明朝》直接认定为 1.0 成品或统一套用全库篇幅 | 标杆逐章通过编辑、来源、场景价值和阅读路径验收 |
| 1.0 · Final Acceptance | 待指令 | 第 09 轮。验收产品定位、视觉、交互、内容、性能、工程和真实使用体验，准备正式发布 | Phase 01–08 的交付和产品负责人验收指令 | 验收未通过即发布，或丢弃旧用户状态与缓存迁移检查 | 按验收标准记录证据、解决阻断项，经产品负责人通过后按版本规范发布 `1.0.0` |

每轮仅执行已明确下达的工作，阶段间保持工程兼容。后续阶段所需但尚未授权的底层变化，可以用明确接口或兼容层承接。已完成阶段的非阻断问题记入最终验收。影响下一阶段实施的阻断问题须由产品负责人确认后修复。

Phase 01–08 通过验收后在本地 `develop/1.0` 提交完整成果，并在 [阶段报告](progress/) 留存验证记录。远程连接正常时建议推送至 `origin/develop/1.0` 供备份与检查。`main` 继续提供稳定线上原型，正式合并在最终验收及发布授权后执行。

Phase 01–06 已完成。Phase 07 按一级风险分批查证，全部审校与验收仍在进行。Phase 08 须等待 Phase 07 验收与产品负责人新指令。
