# 时空地球 1.0 正式发布与回退

本清单供产品负责人授权正式发布时使用。当前 `1.0.0-rc.1` 是开发候选，公开站点继续运行稳定原型。[最终验收标准](ACCEPTANCE.md) · [候选证据](progress/PHASE-09.md)

## 发布前

1. 记录待发布候选及上一个健康线上版本的完整提交。核对构建、快照、脚本和 [16 项矩阵](progress/phase-09/matrix.md)。
2. 由负责人确认人工任务、iPhone 真机、原生辅助技术、Phase 07 完整历史内容和工程问题均已按标准验收。保存正式发布授权。
3. 更新正式版本标识、面向用户的发布记录、README 和下载引用。在干净检出用 Node.js 22 运行内容检查、双构建及适用回归。
4. 核对 `index.html`、`index.offline.html`、`sw.js`、`data/topics.json` 和覆盖报告的字节数及 SHA-256。检查清单的安装身份和相对作用域。
5. 核对 author、committer、GitHub 账号和远端主分支。获授权后合并到 `main`，将测试过的一套文件一起推送。

## 发布后

1. 确认 `main` 的只读构建工作流核对通过，核对 GitHub Pages 的部署提交与实际站点文件。
2. 用干净配置打开站点。检查 1500 年首启、书卷、史事、观察、来源、清单及图标。下载单文件后通过 `file://` 断网打开。
3. 用保留旧缓存的专用配置验证更新。保持旧标签页查看旧版，关闭全部旧客户端再重启，核查新版本、断网启动、阅读位置和其他同源应用的缓存。
4. 记录时区、提交、站点地址、下载哈希、测试环境和核对人。确认站点交付后记录正式标签和发行条目。[源码仓库](https://github.com/lllliam/spacetime-globe) · [Pages 稳定入口](https://lllliam.github.io/spacetime-globe/)

## 回退

1. 记录有问题的提交、缓存版本和复现条件，由负责人决定是否暂停发布。
2. 在独立分支以新提交还原受影响组件，保持路径级缓存隔离和同一版本的 HTML、地图资源及清单。回退到早期原型行为时，把所需修复带入当前缓存机制。
3. 从干净检出重建，复验受影响路径、缓存更新、断网重启及会话。得到授权后以普通提交更新 `main`。
4. 核对 Pages 的回退提交并用新旧两个浏览器配置验证。已打开窗口继续使用原有完整版本，关闭该应用窗口后切换。本地阅读进度沿原存储键读取。
