# 公开部署、正式发布与回退

本清单管理从 `main` 上线的公开维护版本和正式发布。`1.0.0-rc.1` 的授权上线记录见 [CHANGELOG](../CHANGELOG.md)。各类验收及正式发布条件见 [版本规范](VERSIONING.md) 和 [验收标准](ACCEPTANCE.md)。

## 上线前

1. 记录待部署提交、当前健康线上提交、核对人、测试范围与产品负责人的上线授权。需要正式发布时，核对 16 项验收标准、人工、真机、原生辅助技术、实机性能及完整历史内容验收，保存正式授权。
2. 核对版本及兼容性。涉及产品版本时更新包标识、README、CHANGELOG 及受影响规范。在干净检出用 Node.js 22 运行内容检查、在线与离线构建及适用回归。
3. 核对 `index.html`、`index.offline.html`、`sw.js`、`data/topics.json` 和覆盖报告的字节数及 SHA-256，检查清单的安装身份和相对作用域。文档或治理变更比对现有构建的全部这些产物。
4. 核对 author、committer、GitHub 账号及远端 `main`。以普通提交或合并推送验证过的文件。

## 上线后

1. 核对主分支只读构建结果（按工作流路径触发）、Pages 部署提交以及实际站点文件。记录时区、提交、核对人、下载哈希及验证环境。
2. 正式发布或产物变更时，用干净配置验证 1500 年首启、书卷、史事、观察、来源、清单与图标。下载单文件，经 `file://` 断网打开。
3. 正式发布或涉及缓存、迁移时，用保留旧缓存的专用配置测试更新。保持旧标签页验证旧版，关闭相应客户端再检查新版、断网、阅读位置及其他同源应用缓存。
4. 适用时记录正式标签与 GitHub Release，使其与验收基线一致。[源码仓库](https://github.com/lllliam/spacetime-globe) · [公开站点](https://lllliam.github.io/spacetime-globe/)

## 回退

1. 记录问题提交、缓存版本与复现条件，由负责人决定是否暂停发布。
2. 在独立分支以新提交还原受影响组件。保留路径级缓存隔离，使 HTML、地图资源、图标及清单匹配。恢复旧原型行为时沿用现行缓存机制。
3. 从干净检出重建，复验受影响路径、缓存更新、断网重启和会话。授权后以普通提交更新 `main`。
4. 核对 Pages 的回退提交，用新旧两个配置验证旧窗口继续使用完整版本，关闭对应客户端后切换，本地阅读进度沿原存储键读取。
