# 《全球政权史范例编写规范》（以《明朝》卷为标杆）

本规范以精修后的 `data/books/ming.json` 与 `data/scenes.json` 明朝场景为全站样板，用于指导后续全地球、全时期所有政权与国家书卷的扩充与统一验收。

## 一、卷级结构标准（Volume Contract）
- **定位**：一卷即一个完整历史政权/国家（如《明朝》《清朝》《罗马帝国》《奥斯曼帝国》《德川幕府》）。
- **卷首 `summary`（80–120 字）**：用空间脉络概括该政权的“立国地理—运转命脉—全球连接—转折余波”，避免编年史流水账。
- **章节数量**：一般拆为 **4–6 章**，严格满足年份首尾无缝衔接（`chapter.from === prev.to + 1`），每一章对应一次决定性的空间重心转移或结构转折。

## 二、章级信息分层（严禁重复啰嗦）
每一章由 5 个职责清晰、互不重复的层次组成：
1. **`summary`（40–65 字）**：一句话历史钩子，交代本章核心矛盾与结局。
2. **`spatialThesis`（60–95 字）**：本章独一无二的**地理/空间核心论点**，回答“为什么这件事发生在这里、受限于什么山川航路”。
3. **正文 `paragraphs`（每章 6–7 段，3 个清晰节拍）**：
   - **去教材化小标题**：严禁使用 `一、` `二、` `三、` 教科书编号；改用有画面感、动作感或张力的短标题（6–12 字，如《长江上的三角博弈》《天子守国门与双都格局》）。
   - **iPhone 一屏一段原则**：每段控制在 **110–175 汉字**，确保手机端一眼扫完不压迫；必须写出具体的人、物、地点与抉择，而非纯抽象制度名词堆砌。
   - **精准出处**：每段必须附 `refs` 数组指向 `book.sources` 中真实核验的权威文献/博物馆/学术条目。
4. **微观切面 `callout`（每章 1 处，80–120 字）**：
   - 只写一个极具代入感的**微观历史现场**（一仓漕粮、一锭波托西白银、一张税单、四十天两易其主的京师），与宏观正文形成“远景 + 特写”的阅读呼吸感。
5. **横向坐标 `contemporaries`（每章 1–3 条）**：
   - 锚定同时期其他大洲或邻近文明的政权书卷，用一句对照揭示全球共时性（如明朝一条鞭法 ↔ 莫卧儿阿克巴田赋折银）。

## 三、地球场景标准（Scene Contract，`data/scenes.json`）
- **一章 1–3 个高光场景**：挂载在最贴合的段落之后（`sceneRefs: [{ id, after }]`），确保读者刚读完关键转折就能一键飞进地球看空间关系。
- **无孤立点位**：`places` 中每一个地点都应服务于本场景时间窗内的 `routes` 或核心对照；严禁在路线中使用匿名经纬度，所有关键节点必须具名并写清 `role`。
- **多步演进剧本（`steps`）**：优先提供 2–3 个时间步，每步明确 `year`、`title`、`note`、聚焦的 `places` 与 `routes` 索引，让地球能按历史进程“演”出空间推进（例如从波托西银矿跨太平洋飞到福建月港）。
- **校验红线**：每次修改后必须通过 `node tools/verify-content.mjs` 与 `node build.mjs` 全量校验。
