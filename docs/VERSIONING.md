# 版本与发布规范

## 版本沿革

- v0.1 至 v14.2.x 等探索记录归入原型档案，按原名保留其提交、截图与发布记录。[原型更新记录](archive/CHANGELOG-PROTOTYPE.md)
- Phase 01—09 是 1.0 的阶段建设编号。建设已收尾，后续使用产品版本和维护记录。[维护路线](ROADMAP.md)
- 当前公开版本是 `1.0.0-rc.2`。2026-11-25，产品负责人授权首个工程候选在 Phase 07 完整历史审校待续期间上线。2026-11-26 发布移动端与会话修复。[公开记录](../CHANGELOG.md)
- 正式版本从 `1.0.0` 开始。正式发布以后，`1.0.x` 用于修错与细节完善，`1.x.0` 用于核心理念延续下的功能或内容升级，`x.0.0` 用于有重大产品意义的结构性升级。

## 上线、验收与正式发布

| 事项 | 判定依据 |
| --- | --- |
| 公开上线 | 产品负责人授权的版本已从 `main` 部署，在线与离线入口及产物已核对 |
| 工程验收 | 可复现构建、适用回归、浏览器兼容、性能与稳定性结果有实测证据 |
| 人工及真机验收 | 有负责人体验、iPhone Safari 与主屏幕安装、原生辅助技术及代表性设备性能的实测记录 |
| 历史内容验收 | 完成规定范围的史料、论断、地图及来源核查，保存可追溯处置记录 |
| 正式版本发布 | 全部正式验收条件通过，经产品负责人授权，版本、标签及发布记录关联已验收提交 |

Phase 09 工程验收和本次候选上线已有记录。正式 `1.0.0` 仍须满足完整 [验收标准](ACCEPTANCE.md)。

## 分支与发布操作

`main` 为公开产品的主要维护分支。已验范围按授权普通提交或合并推送，复杂或高风险变更可用短期功能分支验证。保留 `develop/1.0` 和其他已有分支，用于阶段证据与工程追溯。禁止强制推送、改写历史及删除历史分支或标签。远端有新增提交时先核对并保留其历史。

每次公开产品更新维护 [README](../README.md)、[CHANGELOG](../CHANGELOG.md) 和受影响的现行文档，记录版本、日期、实际部署提交及已知限制。纯文档或仓库治理可作为维护提交，沿用当前产品版本。

核对 `package.json`、页面与清单的安装身份、生成物、资源和作用域。PWA 缓存由站点路径及构建内容标识自动生成。旧原型的 `globe-v24-icons` 保留兼容，图标 `?v=4`、`scope`、`start_url` 和 `globe.display.v4` 遵循各自的兼容规则。回退以可追溯的新提交记录并验证现有用户进度。[发布操作及回退](RELEASE-CHECKLIST.md) · [维护约定](../AGENTS.md)
