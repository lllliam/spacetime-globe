# 版本与发布规范

## 原型、建设阶段与正式版本

- 从 v0.1、v1 到 v14.2.x，以及仓库实际记录的其他探索版本，统一归入 **Prototype**。相关名称、提交、截图和发布记录按原始身份保留，参见 [原型更新记录](archive/CHANGELOG-PROTOTYPE.md)。
- 1.0 建设采用 `1.0 · Phase 01` 至 `1.0 · Phase 08`，第 09 轮使用 `1.0 · Final Acceptance`。这些名称表示开发阶段。路线和当前进度见 [开发路线](ROADMAP.md)。
- 正式版本从 `1.0.0` 开始，须由产品负责人通过最终验收并授权发布。`1.0.x` 用于修错与细节完善，`1.x.0` 用于核心理念延续下的功能或内容升级，`x.0.0` 用于有重大产品意义的结构性升级。后续阶段不再沿用 `v15`、`v16` 等原型编号。

## 工程标识

现有 `package.json` 的 `14.2.1` 标识原型基线。PWA Cache Storage 名称 `globe-v24-icons`、图标与清单请求的 `?v=4`、地形资源 `terrain-4k-v1.png` 以及本地显示偏好键 `globe.display.v4` 分别按各自兼容与失效需求管理。产品编号调整不触发这些工程标识改名。缓存更新应有明确失效范围，配置数据迁移须验证老用户数据与回退路径。

## 最终发布同步范围

验收阶段核对 `package.json`、`src/shell.html` 的网页标题和应用元数据、`manifest.webmanifest` 的安装名称与图标、`sw.js` 的缓存及迁移策略、资源标识和持久化迁移方案。重新执行验证与构建，核对 `index.html`、`index.offline.html`、生成报告、实际部署产物、README、正式更新记录及 Git 标签／发布条目指向同一验收基线。按验收清单验证 Pages 和下载入口。版本迁移或回退通过保留历史的新提交完成。

Git 保护适用于本地与远端。保留既有提交历史、分支、标签与发布记录，禁止重置、清空、重写历史或重建仓库。提交、推送和正式发布按产品负责人的授权执行，并遵循 [维护约定](../AGENTS.md) 的个人身份要求。

## 开发成果同步

阶段成果统一提交到本地 `develop/1.0`。阶段验收通过后建立本地提交，包含相关源码、在线及离线构建产物和阶段报告。经授权暂存的阶段可先保存检查点，报告注明暂存状态和恢复入口。阶段报告保存在 [docs/progress](progress/)，命名为 `PHASE-NN.md`。

远程连接正常时推荐推送 `origin/develop/1.0` 并核对远端 commit，供检查及备份。远端已有改动时先核对并保留其历史。可选用独立克隆验证完整交付。推送受阻时保留本地成果并如实记录，阶段验收以实现、构建与回归结果为准。

`main` 是稳定线上分支，相关变更会触发 GitHub Actions。第 09 轮的工程验收及部署准备可先开展。所有最终验收条件（含完整历史内容验收）通过并获正式发布授权后，按正式流程合并开发成果并验证 Pages。正式发行后按实际发布维护面向用户的更新记录，包含版本、主要变化、兼容或迁移影响和发布引用。原型历史仍在独立档案中追溯。[开发路线](ROADMAP.md) · [最终验收标准](ACCEPTANCE.md)
