# Historical World 历史世界建设规范

历史内容工程以 `codex/ios-native` 和统一权威内容库为现行基线。产品与工程沿各自路线维护。[维护路线](ROADMAP.md) · [iOS 产品规范](../native-ios/PRODUCT.md)

| 工作 | 交付要求 |
| --- | --- |
| 存量事实与证据 | 优先处置重大事实、年代、身份、数字、引语、因果与伤害叙事。记录材料性质、实际查阅位置、所支持的论断和局限。 |
| 历史主体与疆域 | 分开维护主体身份与存续期、地图记录与覆盖期、书卷与叙事期。史实修订需要可追溯材料。位置、路线、控制和边界各按证据精度呈现。 |
| 完整书卷 | 保留旧身份，按读者能理解的因果和时序组织人物、制度、经济、社会及转型。章节和篇幅随材料确定。禁止虚构人物心理、对白或体验。 |
| 这一年的世界 | 用规范史事、带时间范围的背景、主体及已有联系动态组装。确有依据的事件归入当年发生。复用明确关联的书卷、地点与现场。 |
| 历史现场 | 每幅地图回答一个具体空间问题。记录相关年代、观察阶段、位置和证据。资料不足的点或路径按近似、区域、示意或位置未知呈现。 |
| 全球关系 | 分开标注共时、比较、实际联系、背景和延伸阅读。比较写清维度，接触和因果各有支持材料。 |
| 覆盖与成熟度 | 记录论断、卷章、主体、年份、地区、疆域和现场的覆盖与缺口。区分简明概述、深化书卷和已核论断。成熟度以叙事和证据记录为依据。 |

各地区、群体、文明和政治制度采用同一证据标准。保留关键争议和档案的原始立场。校验器确认数据可以使用，编辑判断落实到论断和史料。[历史编辑规范](EDITORIAL-STANDARD.md) · [史料核查](SOURCE-AUDIT.md) · [历史现场规范](HISTORICAL-SCENES.md)

## 基线与工作批次

1. 从 Phase 06 的 `5bae983` 存量清单与 Phase 07 的 `2d8233b` 内容检查点续接，保留 5,576 的原分母。Phase 08《明朝》的处置只继承到仍匹配的稳定 ID 及材料范围。新增及合并记录单列。[Phase 07 档案](progress/PHASE-07.md) · [Phase 08 档案](progress/PHASE-08.md)
2. 产品负责人可指定优先建设的国家、地区、文明、历史时期或专题。按指定范围和演进顺序集中推进，优先处置范围内的高风险论断，并同步完成书卷、主体与地图、年份和史事、现场、关联及证据。保留其余风险队列。必要的跨区内容随实际联系推进。
3. 一批一份机器可读记录。保留稳定 ID、来源访问、论断、处置、受影响关联及复核范围。现行记录按 ID 合并。既有档案和原证据留在历史路径及提交中。
4. 权威源维护在 `data/`，由 `native-ios/prepare-data.mjs` 编译离线资源。新数据使用既有契约。确需改变对象身份时记录映射，检查引用和进度恢复。[历史内容模型](HISTORY-MODEL.md) · [原生架构](../native-ios/ARCHITECTURE.md)

当前第一优先为中国历史。按历史阶段推进，沿用《明朝》标杆及其他已有成果，补入并存政权、不同地区及民族、边疆、港澳台与周边关系。古代地理依据同代材料，当代条目注明资料截止时间并区分实际管辖、政治主张及历史解释。收到「继续中国历史建设」后直接从[专项检查点](progress/CHINA-HISTORY.md)续接。

现行账目、风险与下一批入口见 [Historical World 检查点](progress/HISTORICAL-WORLD.md)。每批按 [最小必要验证](../AGENTS.md#执行效率与最小必要验证原则) 交付。
