# 设计目标 · 手机版 v2

> 写在前面：这份文档是「为什么长这样」，不是「有什么功能」。功能会变，不变式不会。
> 参考实现：电脑版 `spacetime-atlas`（单 HTML，四种视图）。手机版不是它的缩小版，是同一个数据的另一套身体。

---

## 一句话

**一个球，一条时间轴，一个图层开关。所有深度都藏在地球下面。**

## 五条不变式

这五条优先于任何功能请求；违反它们的方案要重新设计，而不是加开关绕过。

1. **首屏只有三个可点控件**：地球、时间轴、图层开关。没有标签栏、没有侧边栏、没有搜索框、没有设置齿轮出现在首屏。
2. **时间只有一个入口**（时间轴），**图层只有一个入口**（开关）。不许出现「时间选择器 2.0」或「高级图层菜单」。
3. **任何一块陆地都要能点开**，并且回答三个问题：这里是谁、什么时候、发生了什么。点空白也要有答案（海域 / 无人区 / 无记录），不许静默。
4. **所有图层共享同一种「内容热度」语义**：金色越深＝这一年这里的记录越多。切换图层时热度不变、只有边界变，视觉上不能跳。
5. **离线优先、无账号、无后端**：首次访问之后完全断网可用；不依赖任何 CDN、地图瓦片服务或登录态。

## 三层信息架构

| 层 | 载体 | 内容 |
| --- | --- | --- |
| **L0 球面** | WebGL canvas | 内容热度着色、当前图层的边界、选中实体高亮、昼夜光照与大气 |
| **L1 实体档案** | 底部抽屉（可上拉全屏） | 名称（中/英）、存续年、疆域微地图、当年条目、邻居、出处 |
| **L2 这一年** | 长按地球弹出的全屏列表 | 当前年份全世界的条目，按大区分组（v1.0 已有，保留） |

导航只有「下钻」一个方向：球 → 档案 → （条目/邻居）→ 球。任何时候双指下拉都能回到球面。

## 图层（划分方式）抽象

图层不是一堆 if，而是一个统一接口——这是整个设计最值钱的一处抽象：

```ts
type Layer = {
  id: 'country' | 'polity' | string;
  name: string;                     // 界面上显示的中文名
  range: [number, number];          // 支持的年份区间
  /** 该年份的分区：id 图 + 实体表。这是渲染与拾取的唯一来源 */
  partitionAt(year: number): {
    ids: Uint16Array;               // 2048×1024 的 id 栅格（0 = 无归属）
    entities: EntityRef[];          // id → 实体
  };
  entity(id: number): Entity;       // 名称、存续年、几何、来源
};

type Entity = {
  id: number;
  name: string; nameEn: string;
  from: number; to: number;         // 存续年
  kind: 'country' | 'polity' | ...;
  polys: string[];                  // 1000×500 空间的 SVG path
  parent?: number;                  // 宗主/上级（如英属印度 → 大英帝国）
  source?: string;
};
```

**为什么统一成「id 栅格」**：v1.0 已经验证过一条链路——`Path2D → 离屏 canvas 栅格化成 id 图 → 逐像素拾取 → 同一张图喂给着色器`。国家层、政权层、以后的文化圈层只要都能产出这张 id 图，渲染、拾取、高亮、邻居计算全部复用，零分叉。

## 内置图层与数据现状

| 图层 | 数据 | 规模 | 内容 |
| --- | --- | --- | --- |
| **国家**（默认） | 现代国界（Natural Earth，公有领域） | 177 块，静态 | 1512 条年表（中/英/西，带出处） |
| **政权** | Cliopatria（CC BY 4.0，Seshat） | 13,797 个时间切片 / 1,637 个实体 / 前 3400–2024 | 无现成文本：靠**空间-时间关联**挂到年表条目 |
| 以后 | 文化圈 / 宗教 / 语言 | 待定 | 待定 |

实测数据画像（凭 `boundary-pack` 解包统计）：

- 切片格式 `[起始年, 结束年, 英文名, SVG path, 分片号, id, 短名]`，原包 6.4MB base64 → 25.6MB JSON
- 覆盖密度：前 3000 年 4 个 → 前 500 年 48 → 1000 年 133 → 1500 年 141 → 2000 年 192 → **2024 之后为 0**
- 长命实体切片很多：奥斯曼 132、神圣罗马 129、法国 116、大英 110
- 现代国家英文名有 29/89 在 Cliopatria 里同名 → 可以做「同名的历史前身」跳转

**两个必须正视的空洞**：①前 3000 年几乎无政权记录；②2024 之后没有政权数据（现代国家层接住）。界面要显式表达，不能假装有。

## 数据工程（真正的工作量在这里）

现在的 25.6MB JSON 在电脑上无所谓，在手机上不行。重新打包成**可随机访问的二进制 + 按世纪按需拉取**：

```
atlas/
  countries.json       ~25 KB    现代国界（首屏必须有）
  entries.json         ~180 KB   1512 条年表 + 地区表（首屏必须有）
  polity/
    names.json         ~40 KB    1,637 个名称（英 + 中文译名）
    index.bin          ~260 KB   13,797 × {start:i16, end:i16, nameId:u16, off:u32}
                                  + 54 个世纪的覆盖位图（54 × 13,797 bit ≈ 93 KB）
    geom.bin           ~3.5 MB   几何，按切片切段，gzip 后随机访问
```

客户端流程：年份变了 → 查世纪位图得到「该年需要的切片集合」（实测 1500 年 141 个／2000 年 192 个）→ 从 `geom.bin` 拉缺的那几段（典型 60–250 KB，带 LRU 缓存）→ 栅格化 → 出图。

- **首屏**：countries + entries + names + index ≈ **350 KB**
- **换世纪**：按需 60–250 KB；滑动时后台预取相邻两个世纪
- **全量**：约 4 MB，只在用户真的横扫全时间轴时才会拉完

几何压缩手法（按收益排序）：坐标量化到 1/8 度存 int16 → 相邻点 delta + varint → 相同 path 去重（同一政权相邻年份经常完全一样，比如俄国 1900–1904）→ 最后整段 gzip。

**中文名**：1,637 个实体里高频的约 200 个（帝国、王朝、汗国、殖民政权）人工校对，其余先留英文并在界面上标注「译名待补」。宁可显示英文，也不要出现错译的「某某王朝」。

## 内容关联（「点进去看什么」的真正来源）

政权层没有现成文本，所以档案页的内容全部由**几何 + 时间**算出来：

1. **给每条年表条目一个代表点**：取它所属地区现代国界的质心（1512 条，一次性算好存进 entries.json）。
2. **当年条目** = 代表点落在该政权当年疆域内 ∧ 条目时间区间与政权存续期相交。
3. **邻居** = 当年 id 栅格上与该政权像素相邻的其他 id（一次洪泛即可，适合做「同时期的邻居」）。
4. **疆域变化** = 该政权所有切片的并集按年播放（时间轴上一条「生命线」，见 Phase 2）。
5. **出处**：Cliopatria 的 polity id 可以链到 Seshat / Wikidata，作为「更多资料」的外链（在线时可用）。

这样「点进奥斯曼帝国」看到的是：1453–1922 的存续、当年疆域、当期发生在疆域内的 12 条年表条目、同期接壤的 8 个政权、以及疆域随年份的收缩动画。**没有一个字是新写的文本，全部是从已有数据里算出来的关系。**

## 交互设计（首屏只有一个球，怎么让人发现"能点"）

- **发现**：进入 3 秒后自转停下，在一两个记录最密的国家上闪一次金色脉冲（只闪一次，不循环）。
- **时间在动的最强反馈**：拖时间轴时，球面上有一条「年份光带」从左扫到右，同时热度重算。
- **图层切换**：时间轴右端一个胶囊 `国家 | 政权`；切换时边界 260ms 淡入淡出，热度色不动。
- **点空白**：一行小字「这里是海」，出现一次后不再打扰。
- **长按地球 500ms** → L2「这一年」；双击 → 放大到 2.2×；pinch 1×–6×，缩放时实体名标签分三级出现（只在放大后显示政权名，避免杂乱）。
- **档案顶部有 96×48 的疆域微地图**：球上的选区与微地图联动，帮助判断「这是哪一块」。
- **键盘/桌面**：← → 逐年，Shift 二十年，+/- 缩放，Esc 关闭（v1.0 已有，保留）。

## 性能与体量预算（iPhone 12 / 中端安卓基准）

| 指标 | 预算 | 现状（v1.0） |
| --- | --- | --- |
| 首屏可交互 | < 1.2 s | ~0.9 s（数据更小） |
| 换年份到重绘完成 | < 80 ms | ~20 ms（只重算热度） |
| 换图层（栅格化 13k 切片） | < 120 ms | 未实现，需实测 |
| 滚球帧率 | 60 fps | 35–60 fps（无头软件渲染下 35） |
| 空闲帧 | 0 | 0（自转 22 s 后停） |
| 首屏传输 | < 400 KB | 0.68 MB（单文件全内嵌） |

## 分期

- **Phase 0（已完成 = v1.0）**：WebGL 球体、时间轴、国家层、拾取与画面严格一致、空闲即停、离线可更新。
- **Phase 1（政权层跑通）**：重打包数据 → 图层开关 → 拾取 → 档案页最小版（名称 / 存续 / 疆域 / 当年条目 / 邻居）。
- **Phase 2（深度）**：实体生命线（点帝国，时间轴上出现它的存续段）、疆域变化动画、中文名补齐、同名历史前身跳转。
- **Phase 3（第三图层 / 内容）**：文化圈或宗教图层（数据待定），或离线预取 Wikipedia 摘要。

## 需要拍板的三个决定

1. **译名策略**：高频 200 个人工译，其余留英文标「译名待补」——接受，还是宁可不显示英文？
2. **条目归属算法**：用「代表点在疆域内」关联（会有边缘误挂），还是只显示「所在现代国家 + 政权存续期」的保守版本？
3. **数据加载**：全量一次性 4 MB 下载（体验最顺，首屏变慢），还是按需流式（首屏 350 KB，滑时间轴可能等 100–250 ms）？我倾向：首屏流式 + 空闲时后台预取全量。
